# Site Architecture

## Stack

Plain HTML, CSS, and vanilla JavaScript. No framework, no build step, no dependencies to install. The only external resources are Google Fonts, loaded via `<link>` tags.

This is intentional: the site is a single deliverable meant to be opened, edited, or deployed by anyone without a dev environment.

## File structure

```
cftfip/
├── index.html          # the entire site — markup, styles, and script in one file
├── README.md            # quick-start overview for repo visitors
├── LICENSE
├── docs/                 # this documentation
└── screenshots/         # images used in README.md
```

Everything — HTML, CSS, and JS — lives in `index.html`. For a page this size, splitting into separate `.css`/`.js` files would add file-hopping overhead without a real benefit. If the site grows significantly (multiple pages, a CMS, dynamic data), that's the point to split it out.

## Section-by-section breakdown

`index.html` is organized top-to-bottom in the same order content appears on the page:

| Section (`<section class="...">`) | Purpose |
|---|---|
| `.hero` | Title, mission statement, opening quote, scroll cue |
| `.context` | The problem: narrative + statistics grid |
| `.pillars` | The four project pillars, each with a description and indicator tags |
| `.me` | Monitoring & evaluation: plan-building steps + reporting cadence |
| `.budget` | Animated budget ledger, populated from a JS data array |
| `.location` | Target location narrative + a decorative map sketch (SVG, not a real map) |
| `.contact` | Call to action + contact links |

## Data-driven parts

Two things are generated by JavaScript rather than hardcoded in the HTML, so they're easy to update in one place:

1. **Budget ledger** (`budgetItems` array near the bottom of the file) — each entry is `[name, amount]`. The total, percentages, and bar widths are all calculated from this array. To update the budget, edit this array only — do not hand-edit the ledger rows in HTML, since there are none; they're rendered at runtime.
2. **Scroll reveal animations** — any element with class `reveal` is faded/slid into view via `IntersectionObserver` when it scrolls into the viewport. Add the `reveal` class to any new block you want animated.

## Adding a new section

1. Add a `<section>` following the existing pattern (see any current section for the eyebrow → heading → content structure).
2. Reuse existing CSS custom properties (`--maize`, `--brick`, `--cream`, etc. — defined in `:root`) rather than introducing new colors.
3. Add the `reveal` class to elements you want to animate in on scroll.
4. If it holds a list of line items (like the budget), consider generating it from a JS array rather than hardcoding rows, for the same reason the budget is.
